# TapX 工作原理

TapX 将配置控制面与高速数据面分开：Go 控制面负责 Web/API、对象校验、数据库、运行配置、生命周期、日志和统计；Raw UDP/TCP 与 TAP/TUN 的高频路径由 C FastPath 处理；内置 Xray 与外置 Xray 通过统一适配层接入。

## 流量处理链

1. 流量从系统网卡、TUN/TAP、监听端或已建立的隧道进入。
2. 接入控制按需检查用户、vKey、源地址、MAC、有效期、额度与速率。
3. 接入分流、终端分流和 DNS 分流根据源终端、目标、域名、GeoData 与规则集匹配策略。
4. 路由组和负载均衡选择直连、阻断、本机网卡或具体连接端。
5. TapX Raw、内置 Xray 或外置 Xray 执行真实传输。
6. 面板从运行时回读状态、流量、速度、延迟、错误和诊断结果。

## 对象模型

TapX 不把复杂网络限制为固定套餐。网卡、设备、监听端、连接端、用户、vKey、路由、地址限制和规则集分别保存，再通过引用自由组合。保存时检查字段结构与对象引用，应用时检查设备、端口、路由、管理链路和运行内核能力。

未配置的功能不会被加入数据面热路径；已配置的功能在运行前完成解析和准备，逐包路径不会读取数据库、解析 JSON 或执行 shell 命令。

## 三种运行内核

- **TapX Raw FastPath**：Raw UDP/Raw TCP、TUN/TAP 与高吞吐转发。
- **内置 Xray**：面板管理的同进程官方 Xray Core 传输。
- **外置 Xray**：由 TapX 生成配置并管理的独立 Xray 进程。

三种内核共享统一的连接端、路由、用户、状态和诊断模型，但各自只展示真实支持的字段与检测能力。

## 保存、应用与回滚

新增、编辑或删除单个对象会直接保存对象。接入分流、终端分流和 DNS 等组合配置页使用统一“应用配置”语义。运行应用失败时返回具体原因，并保留或恢复上一份可用运行配置；“重载配置”只重新读取已保存配置，不代替保存。

## 诊断

代理出站诊断经过所选连接端的真实代理协议，包含 TCP/HTTP、协议支持时的真实 UDP 请求延迟、出口信息和 Speedtest。诊断结果、连接端流量、运行状态、错误原因和必要的抓包证据应指向同一条数据路径。
