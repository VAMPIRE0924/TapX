# 常见故障排查

## 面板无法打开

1. 检查 `tapx-panel` 服务是否运行以及实际监听端口。
2. 确认访问地址包含正确协议、端口和登录入口路径。
3. 检查 HTTPS 证书、系统防火墙、反向代理和端口占用。
4. TapX 面板管理员凭据不是 SSH、LuCI 或系统 root 凭据。

## 服务启动失败

```bash
systemctl status tapx-panel tapx-core
journalctl -u tapx-panel -u tapx-core --since today
```

OpenWrt 可使用：

```sh
/etc/init.d/tapx-panel status
/etc/init.d/tapx status
logread | grep -i tapx
```

重点检查配置校验错误、端口冲突、网卡不存在、证书权限、数据库连接和外置 Xray 路径。

## 连接端启用但状态为停止

“启用”不是运行成功。检查目标地址、端口、协议参数、证书/密钥、运行内核、绑定设备、上游连接端以及运行时错误。使用行级诊断确认失败发生在 DNS、TCP、TLS、代理握手、UDP 请求还是测速阶段。

## 诊断与业务流量不一致

确认诊断选择的是同一连接端和节点，并同时核对：

- 路由组最终选择的出口；
- DNS 解析结果和 DNS 出口；
- 连接端流量计数与实时速度；
- Xray/TapX 运行日志；
- 入口、代理出口和物理网卡上的抓包。

## 保存或应用很慢

先区分对象保存、数据库写入、运行配置生成、服务重载和远程节点调用。浏览器中出现多个相同配置请求时应检查重复 API 拉取；不能通过截断数据、长时间缓存旧响应或减少字段来掩盖耗时。

## OpenWrt 包无法安装

- `apk` 设备必须使用 `.apk`，`opkg` 设备必须使用 `.ipk`。
- 检查 CPU 架构、OpenWrt 固件、软件源和内核 ABI。
- 确认 `/overlay` 空间充足。
- 不要通过改扩展名或忽略依赖强制混装不同格式。

## 升级后页面或版本未更新

确认 Release 标签、manifest、面板版本、核心版本和内置 Xray 版本一致。清理浏览器缓存前先确认服务端静态资源已经更新；不要删除数据库、证书或配置作为第一步排障。

提交问题前请阅读 [支持说明](../SUPPORT.md)，并对日志和截图进行脱敏。
